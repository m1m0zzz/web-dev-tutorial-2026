| # | 指摘 | 確認した事実 | 対応 |

| 2 | `git config user.name` / `user.email` が「つまずきポイント」の中にあるが、実際には 1.8 の最初のコミットに必須 | Windows 側の設定は WSL に引き継がれない。未設定なら `Author identity unknown` で止まる | **1.5 の本手順に格上げ。** 確認方法（`git config --global --get user.email`）と、コミットに記録され公開されうることも書いた |

| 8 | 「npm workspaces はルートが private であることを前提としている」は誤り | **実際に private 無しの workspace を作り、`npm install` が通ることを確認した** | 「必須条件ではないが、誤公開防止のため付ける」に訂正。各 workspace にも個別に必要であることも明記 |
| 9 | 「`nvm alias default` を設定しないと `node: command not found` になる」は誤り | **`~/.nvm/nvm.sh` の `nvm_ensure_default_set` を確認。** default が未設定なら、インストール時に自動で作られる | 「初回なら省略しても動く。明示するのは、特定のバージョンではなく LTS ラインを指させるため」に訂正 |

| 6 | `npm config set min-release-age 3` はユーザー全体に効くのに、影響範囲も戻し方も確認方法も無い | — | `npm config get min-release-age` を確認方法として追加。影響範囲と、`--min-release-age 0` / `npm config delete` での回避も書いた |
| 3 | 「`cdnvm` 関数を貼り付けます」だけでは、どこからどこまでコピーするか分からない | **手元の `.bashrc` を確認。** 実際の範囲は `cdnvm() {` から `cdnvm "$PWD" \|\| exit` まで（`alias cd='cdnvm'` を含む） | コピー範囲、`code ~/.bashrc` で開くこと、`source ~/.bashrc` での反映を明記 |
| 5 | 「扱うこと」に「権限設定」とあるのに、本文に説明が無い | — | 「権限の扱い方」として本文を追加。確認を省略する設定にしないこと、`git diff` を挟むことを書いた |
| 10 | 「ネイティブインストーラなら自動更新」が、Claude Code と Codex の両方に効くように読める | Codex は更新もインストールスクリプトの再実行 | 製品ごとに分けた |
| 11 | `npm audit` を対策として挙げているが、記事のどこでも実行しない | `docs/**` と `.github/workflows/**` を検索して確認 | 「この記事では扱わない」と明記 |
