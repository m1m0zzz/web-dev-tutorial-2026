## コードの修正を伴うもの

### #1 ユーザー ID が、サインアップ後に変更できてしまう

**実機で確認しました。** `POST /auth/update-user` に `{"userId":"hijacked"}` を送ると 200 が返り、`get-session` の `userId` が実際に書き換わりました。さらに悪いことに、**この経路には作成時の検証が効きません。**

| 操作 | 修正前 |
|---|---|
| サインアップで `userId: "public"`（予約語） | 400（正しく弾かれる） |
| 更新で `userId: "public"` | **200。変更された** |
| 更新で `userId: "Akira"`（大文字を含む） | **200。変更された** |

原因は `additionalFields` の `input: true` が**更新時の入力も許可する**ことと、検証が `databaseHooks.user.create.before` にしか無いことです。記事は「ユーザー ID は変更不可」と書いており、[7.4](../docs/07_features.md#74-ユーザーページ-usersuserid) の `/users/:userId` はこれが変わらない前提で公開されます。

**`databaseHooks.user.update.before` で `userId` を含む更新を拒否する形にしました。** 修正後に再度実機で確認しています。

| 操作 | 修正後 |
|---|---|
| 更新で `userId` を変更 | **400。値は変わらない** |
| 更新で `name`（表示名）を変更 | 200。正しく変わる |

`npm test -w apps/api`（13件）、`typecheck`、`lint`、`format:check` はすべて通ります。**この振る舞いを固定するテストは 4.2 に追加すべきですが、まだ入れていません。**
