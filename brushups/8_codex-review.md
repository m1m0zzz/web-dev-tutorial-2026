# 8章 codex レビュー（2026-08-23）

[`docs/08_e2e.md`](../docs/08_e2e.md) のレビュー結果です。12件すべてに対応しました。**うち4件はコードの修正**です（8章のコミット）。

## コードの修正を伴うもの

### #5 E2E を走らせると、開発中のローカルデータが消える

`webServer` のコマンドが `rm -rf apps/api/.wrangler/state/v3/d1` を実行していました。**これは `npm run dev` が使う通常のローカル D1 で、手動で確認するために作ったユーザーやメモも一緒に消えます。**

`--persist-to .wrangler/e2e` で **E2E 専用の保存先**に分け、消すのもそちらだけにしました。マイグレーションと `wrangler dev` の両方に同じ指定が要ります。実際に走らせて、専用ディレクトリが作られ、通常の D1 が残ることを確認しています。

### #3 失敗時の artifact が空になる

`reporter` は `dot` / `list` で、どちらも端末に出すだけです。**`playwright-report/` を生成するのは HTML reporter なので、CI でアップロードしても中身がありません。** 切り分け用の資料を約束しているのに、取得できない状態でした。

CI のときだけ HTML reporter を併用するようにしました（`[['dot'], ['html', { open: 'never' }]]`）。

### #6 ログイン機能を通るテストが1件も無い

7件とも `signUp()` で新規登録してそのまま操作しており、**ログイン画面への入力は一度も実行されません。ログインが壊れていても全件通ります。**

**「ログアウト → メールアドレスとパスワードでログイン → 自分のメモが戻る」というシナリオを追加**しました。E2E は7件 → **8件**になります。

### #11 e2e ジョブに safe-chain が無い

`ci.yml` の `e2e` ジョブは独立していて、自分で `npm ci` を実行します。**`check` ジョブに入れた safe-chain はジョブをまたいで引き継がれません。** 同じ導入ステップを `e2e` ジョブにも入れました。
