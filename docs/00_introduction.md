# イントロダクション

このチュートリアルでは、フロントエンドに始まり、バックエンド、そしてフロントエンドからバックエンド API を呼ぶところまで、Web アプリ開発を体系的に学びます。ハンズオン形式で、実際に手を動かしながら進めます。

**最終的に、認証付きの公開メモアプリを Cloudflare にデプロイします。**

完成したアプリ: https://memo-app-web.m1m0zzz.workers.dev

執筆の一部に Claude を使用しています。

## この記事について

### 作るもの

「メモアプリ」と呼んでいますが、認証と公開範囲の制御が入るため、画面、ルーティング、API、データベース、認証と認可、テスト、デプロイと、Web アプリを作るのに必要なものはひととおり出てきます。

- メールアドレスとパスワードでのサインアップとログイン
- メモの作成・編集・削除（自分のメモだけ）
- メモごとの公開 / 非公開の切り替え
- 公開されたメモの一覧ページ（ログインしていなくても読める）
- ユーザーごとの公開メモのページ
- 単体テストと E2E テスト
- Pull Request でテストが走り、`main` にマージすると、変更のあった側だけが自動でデプロイされる状態

**全体の形はこうなります。** ブラウザで動く React の画面が、Hono で書いた API を呼び、API が D1（Cloudflare のデータベース）にデータを保存します。画面と API は**別々の Cloudflare Worker** としてデプロイし、GitHub Actions がテストとデプロイを行います。それぞれが何なのかは、各章で順に説明します。

### 何ができるようになるか

**このチュートリアルの目的は、写経を終えることではありません。** エラーが起きたときに、何を見ればいいかが分かるようになることです。そのため、各節には「つまずきポイント」を置き、うまくいく手順だけでなく、**失敗したときに何が起きているのか**を書いています。

読み終えると、次のことができるようになります。

- エラーメッセージを最後まで読み、フロント・API・データベースのどこで失敗したのかを切り分ける
- 「動くコード」と「安全なコード」を区別する。特に**他人のデータが見えてはいけない**という要件を、テストで担保する
- 一次情報（公式ドキュメント）を読んで、記事に書かれていないことを自分で調べる

### 想定読者

**必要なもの**

- 何らかのプログラミング言語で、プログラムを書いたことがある
- HTML と CSS を見て、だいたい何が書いてあるか分かる
- ターミナルでコマンドを打てる（`cd` や `ls` が分かれば十分です。[1.6](01_setup.md#16-ターミナル操作に慣れる) で補います）
- Git で commit と push ができる

**不要なもの**（この記事の中で説明します）

- JavaScript / TypeScript の経験（[2.2](02_frontend.md#22-モダン-javascript-の前提知識) で必要な JavaScript を、[2.3](02_frontend.md#23-typescript-と-jsx-の読み方) で型注釈と JSX の読み方を扱います）
- React などのフレームワークの経験
- Node.js / npm のエコシステムの知識
- SQL とデータベース設計
- 認証・認可の実装経験
- テストや CI/CD の経験

### 前提環境

Windows + WSL2 (Ubuntu) を前提としています。macOS / Linux を使っている場合は [1.1](01_setup.md#11-wsl2-ubuntu) を読み飛ばし、[1.3](01_setup.md#13-nvm) から始めてください。

### 費用

**この記事の範囲は、すべて無料でできます。** Cloudflare のアカウントは作りますが（[3.1](03_backend.md#31-cloudflare-アカウント作成--wrangler-login)）、使うのは無料プランの範囲です。GitHub も Public リポジトリなら Actions の実行を含めて無料です。Private リポジトリの場合も、GitHub Free には Actions の標準ランナーが月 2,000 分含まれます。この記事で組む CI がこれを使い切ることはありません。

**どちらも、支払い方法を登録しなければ課金されません。** 上限を超えたときに起きるのは請求ではなく停止です。Cloudflare は Worker がエラー（1027）を返すようになり、GitHub Actions は実行がブロックされます。**「気づかないうちに請求が来ていた」ということは起きない**ので、安心して進めてください。

参考:

- https://developers.cloudflare.com/workers/platform/pricing/
- https://docs.github.com/ja/billing/managing-billing-for-your-products/managing-billing-for-github-actions/about-billing-for-github-actions

### 進め方

記事本文には、初出のコードは全文を、そこからの変更は差分を載せています。

各章には、その章を**終えた**時点のコードのブランチ（`chapter-01` 〜 `chapter-08`）が対応しています。章とブランチの対応は [README](../README.md) の表にあります。`main` は全章を終えた状態です。

このリポジトリは、自分のリポジトリに `tutorial` という名前の remote として足しておきます（[1.8](01_setup.md#18-リポジトリと-workspace-を作る) で設定します）。**詰まったときに、自分のコードと完成形の差分をその場で見られます。**

```bash
git diff tutorial/chapter-04 -- apps/api/src          # 自分のコードと4章の完成形の差分
git show tutorial/chapter-04:apps/api/src/index.ts    # 完成形をそのまま読む
```

**途中の章から始めることもできます。** ブランチは「その章を終えた状態」なので、**N章を自分で進めたいなら `chapter-(N-1)` を取り込みます。** 3章から始めるなら、2章を終えた状態である `chapter-02` です。

```bash
git checkout tutorial/chapter-02 -- .    # 2章までのファイルを自分のリポジトリに展開する
git commit -m "2章までの状態から始める"
npm install
```

> [!NOTE]
> **章ブランチには記事（`docs/`）が入っていません。** 記事は `main` にしかないので、GitHub 上で読んでください。

見出しに「任意)」と付いた章・節は、**読み飛ばして構いません。** 本筋に必要ではないが知っておくと役に立つこと（開発ツール、React の内部の仕組み、レンダリング方式の比較など）をまとめてあります。

### 詰まったときは

順番に試してください。**「動かないから書き直す」は最後の手段です。** 原因が分からないまま直しても、次に同じ症状が出たときに何も残りません。

1. **エラーメッセージを最後まで読む。** 長くても、原因はたいてい最初か最後の数行にあります
2. **その節の「つまずきポイント」を見る。** 既知の罠はほぼそこに書いてあります
3. **節に書かれている確認方法**（「〜と表示されれば成功です」）と実際の出力を突き合わせ、どこまで進んでいるのかを確定させる
4. **章ブランチとの差分を取る。** `git diff tutorial/chapter-04 -- apps/api/src` のようにすると、完成形との違いが分かります
5. それでも分からなければ切り分ける（どのプロセスが落ちているか、どのリクエストが失敗しているか、環境変数は渡っているか）

**この5つだけで進められます。** [1.9](01_setup.md#19-任意-claude-code--codex) は任意の節ですが、AI エージェントを入れた場合は、エラーメッセージごと相談するのも有効です。ただし**答えを書かせるのではなく、原因を一緒に絞り込む**使い方をしてください。
