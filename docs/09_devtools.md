# 9 任意) 開発環境をさらに整える

ここまでで、アプリの開発からデプロイまでが一通り動く状態になりました。この章では、日々の作業を効率化するツールを紹介します。**いずれも必須ではありません。**

## 9.1 ghq + fzf でリポジトリを移動する

[1.7](01_setup.md#17-任意-ghq) で入れた ghq は、リポジトリを `~/ghq/github.com/{ユーザー名}/{リポジトリ名}` に置きます。パスが規則的になる代わりに深くなるので、`cd` で手打ちするのは現実的ではありません。一覧から絞り込んで移動できるようにします。

**扱うこと**

- `fzf` のインストール
- `ghcd`（`ghq list` の結果を `fzf` で絞り込んで `cd` する）

### fzf

標準入力で受け取った行を対話的に絞り込み、選ばれた行を標準出力に返すツールです。「一覧を出すコマンド」と「選んだものを使うコマンド」の間に挟む部品として使います。

**この節では、[1.6](01_setup.md#16-ターミナル操作に慣れる) で扱わなかった記法が出てきます。**

| 記法 | 意味 |
|---|---|
| `A \| B` | A の出力を B の入力に渡す（パイプ） |
| 終了ステータス | コマンドが返す数値。**0 が成功、それ以外が失敗**です |
| `A \|\| B` | **A が失敗したときだけ** B を実行する（`&&` の逆） |

インストール方法は以下のリンクを参照してください。

https://github.com/junegunn/fzf#installation

`ghq list | fzf` を実行して絞り込みの画面が出れば成功です。文字を打つと候補が絞られ、Enter で選ぶとその行が標準出力に返ります。

**つまずきポイント**

> [!TIP]
> - **`apt` で入る fzf は、Ubuntu のリリースによってはかなり古いです。** 執筆時点の手元（Ubuntu 22.04）では 0.29.0 で、本家の最新は v0.74.3 でした。新しいリリースの Ubuntu ならもっと新しいものが入ります。**この節の用途（`ghq list | fzf`）なら `sudo apt install fzf` で十分です。** 公式ドキュメントに出てくるオプションが効かないと感じたら、そのときに上のリンクの方法で入れ直してください
> - Ctrl-C か Esc で中断できます。そのとき fzf は何も出力せず、終了ステータスは 130 になります

### ghcd

`ghq list` は、ルートからの相対パスを1行ずつ返します。

```
github.com/m1m0zzz/web-dev-tutorial-2026
```

ルート自体は `ghq root`（既定では `~/ghq`）で取れるので、この2つをつなげば移動先が決まります。`$HOME/.bashrc` の末尾に次を追加します。

```bash
alias ghcd="cd \$(ghq root)/\$(ghq list | fzf)"
```

ターミナルを開き直して `ghcd` を実行し、一覧から選んだリポジトリに移動できれば成功です。

中断したときに何もしないようにするなら、alias ではなく関数にします。**先ほど追加した `alias ghcd=...` の行を削除してから**、次を書いてください。

```bash
ghcd() {
  local repo          # この関数の中だけで使う変数
  repo=$(ghq list | fzf) || return   # 中断されたら何もせず抜ける
  cd "$(ghq root)/$repo"
}
```

**alias を残したまま関数を書くと、ターミナルを開くたびにエラーが出ます。**

```
.bashrc: line 3: syntax error near unexpected token `('
```

`ghcd` という名前が alias として展開されてから関数定義として読まれるためです。

**つまずきポイント**

> [!TIP]
> - **alias の中の `$` はエスケープしてください（`\$`）。** ダブルクォートの中に `$(...)` をそのまま書くと、alias を**定義した時点で**1回だけ実行され、以後その結果に固定されます。シェルを起動するたびに fzf が立ち上がることになります
> - **alias 版は、fzf を中断すると `~/ghq` に移動します。** 選択結果が空文字列になり、`cd $(ghq root)/` が実行されるためです。害はありませんが、意図した動きではありません。上の関数版はこれを `|| return` で防いでいます
> - `ghq list -p` は絶対パスを返すので、`cd $(ghq list -p | fzf)` とも書けます。`ghq root` を呼ばずに済む代わりに、一覧に表示される行が長くなります

## 9.2 herdr

複数のコーディングエージェントを同時に動かすときに、ターミナルのワークスペースを管理するツールです。どのエージェントが作業中で、どれが入力待ちかを一覧できます。

**注記**

エージェントを複数並行して動かすようになってから価値が出るツールです。1つのエージェントを使っている段階では、通常のターミナルで十分です。

インストール方法は以下のリンクを参照してください。**`herdr` を起動して、ワークスペースと各エージェントの状態が一覧で表示されれば成功です。**

https://herdr.dev/

## 9.3 その他

ここまでで扱わなかったもののうち、次に手を出すと効果が分かりやすいものを挙げます。**どれも必須ではありません。**

**シェルのプロンプト**

今いるディレクトリ、Git のブランチ名、変更の有無をプロンプトに出しておくと、**`git status` を打つ回数が目に見えて減ります。** [Starship](https://starship.rs/ja-JP/) は Git の状態や Node.js のバージョンを既定で表示し、カスタマイズは TOML ファイル1つで済みます。

導入には、バイナリのインストールに加えて `.bashrc` への1行（`eval "$(starship init bash)"`）が必要です。記号を正しく表示するには、対応したフォントも要ります。

**`.editorconfig`**

インデントの幅、改行コード、末尾の空白の扱いを、**複数のエディタで共有する**ためのファイルです。`indent_style`、`end_of_line`、`trim_trailing_whitespace` あたりをよく使います。**エディタが対応していて初めて効きます**（VS Code は拡張機能を入れると読むようになります）。

参照: https://editorconfig.org/

**[2.10](02_frontend.md#210-oxlint--oxfmt-のセットアップ) の oxfmt と役割が重なりますが、対象が違います。** oxfmt が整形するのは JavaScript / TypeScript / JSON / CSS などで、`.editorconfig` はそれ以外のファイル（設定ファイル、Markdown、スクリプト）にも効きます。**複数人で書くリポジトリでは入れておくと、差分が空白だけで汚れることを防げます。**

**コミット前の自動チェック**

コミットしようとしたときに Lint と整形を自動で走らせる仕組み（husky + lint-staged など）があります。**CI で落ちる前に手元で気づけます。** ただし、**入れる前に CI が整っていることが前提です。** 手元のフックは `git commit --no-verify` で飛ばせますが、**CI は共有の環境で毎回実行され、結果が記録に残ります。** 順番を逆にしないでください。
